NICo is installed in {{ .Values.namespaces.nico }}.

Check it:

  kubectl -n {{ .Values.namespaces.nico }} get pods
  kubectl -n {{ .Values.namespaces.nico }} rollout status deployment/nico-api
{{- if .Values.certManager.issuer.create }}
  kubectl get clusterissuer {{ .Values.certManager.issuer.name }}
  kubectl -n {{ .Values.namespaces.nico }} get certificates
{{- end }}

The schema is created and migrated by the migration job in the nico-api
subchart. Nothing is run by hand:

  kubectl -n {{ .Values.namespaces.nico }} get jobs

{{- if .Values.certManager.issuer.create }}

The ClusterIssuer {{ .Values.certManager.issuer.name }} is a SELF-SIGNED CA
created by this chart, not Vault PKI. It has no revocation, no audit trail and
no rotation story, and its private key is a Secret in this cluster. Use it for
a kind cluster or a test lane only.
{{- end }}
